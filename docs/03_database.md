# Database Schema - Heladería Dibuluc (MVP)

## Tables

### `products`
- `id` (INTEGER, PRIMARY KEY, GENERATED BY DEFAULT AS IDENTITY)
- `name` (VARCHAR(255), NOT NULL)
- `description` (TEXT)
- `price` (DECIMAL(10, 2), NOT NULL)
- `stock` (INTEGER, NOT NULL)
- `image_url` (VARCHAR(255))
- `category` (TEXT, NOT NULL, DEFAULT 'boli', valores: `boli`, `vasito`)
- `is_active` (BOOLEAN, NOT NULL, DEFAULT true) # Oculta un sabor sin borrarlo

### `orders`
- `id` (INTEGER, PRIMARY KEY, GENERATED BY DEFAULT AS IDENTITY)
- `customer_name` (VARCHAR(255), NOT NULL)
- `customer_phone` (VARCHAR(20), NOT NULL)
- `total_amount` (DECIMAL(10, 2), NOT NULL)
- `order_date` (TIMESTAMP, NOT NULL)

### `order_items`
- `id` (INTEGER, PRIMARY KEY, GENERATED BY DEFAULT AS IDENTITY)
- `order_id` (INTEGER, NOT NULL, FOREIGN KEY references `orders`.`id`)
- `product_id` (INTEGER, NOT NULL, FOREIGN KEY references `products`.`id`)
- `quantity` (INTEGER, NOT NULL)
- `price_at_purchase` (DECIMAL(10, 2), NOT NULL) # Precio del producto al momento de la compra

## Relationships

- One-to-many entre `orders` y `order_items`
- One-to-many entre `products` y `order_items`

## Constraints

- `products.stock` no puede ser negativo
- `products.price` no puede ser negativo
- `order_items.quantity` debe ser mayor a 0

## Funciones

Las piezas internas viven en el esquema `private`, que no se expone por la API.

- `private.validate_order_customer(nombre, teléfono)` — valida los datos del cliente y los devuelve sin espacios sobrantes
- `private.normalize_order_items(items)` — valida la lista, aplica los topes (30 líneas, 100 unidades por producto) y suma las líneas repetidas
- `private.reserve_product_stock(producto, cantidad)` — bloquea el producto, comprueba y descuenta el stock
- `private.save_order(nombre, teléfono, líneas)` — guarda el pedido y sus líneas, y calcula el total
- `public.create_order(p_customer_name, p_customer_phone, p_items)` — único punto público para crear pedidos; une las piezas anteriores en una sola transacción

Errores de `create_order`, en el campo `message`: `INVALID_CUSTOMER`, `INVALID_ITEMS`, `PRODUCT_NOT_FOUND`, `OUT_OF_STOCK`.

## Endpoints (MVP)

- `GET   /api/products` — listado de productos
- `PATCH /api/products/:id/stock` — descuenta stock al confirmar pedido
- `POST  /api/orders` — crea pedido + order_items en una sola operación
